# Blockbench handoff: animated Arcane Tome and chess set

The runtime target is **GeckoLib 5.5.7 for Minecraft 26.3**. Keep the style blocky and readable at Minecraft distance. Use cuboids and a 16/32/64 pixel texture atlas; avoid high-poly meshes, smooth shading, and tiny details that disappear in-game.

An initial editable source project is present at `assets/blockbench/arcane_tome.bbmodel`, with one opening-cover clip. It has not been reopened in Blockbench or visually checked in Minecraft.

## What the current code actually loads

- The placed Tome is rendered by GeckoLib from this project, exported to `src/main/resources/assets/arcane/geckolib/models/block/chessboard.geo.json` and `src/main/resources/assets/arcane/geckolib/animations/block/chessboard.animation.json`. It currently has only the `root`, `cover`, and `spine_gilt` bones and one 0.7-second opening animation. The runtime controller looks for the bone `cover` and animation `animation.arcane.chessboard.open`; preserve those names until the Java code is deliberately changed.
- The visible chessboard and all chess pieces are currently generated by Java in `BoardSceneRenderer` and `ChessBoardSceneSource`. A Blockbench board or piece export will **not** appear in game until we wire it into the renderer. The planned six piece projects and deployed page geometry are an art handoff for a later integration step.
- The held/inventory Tome uses a separate static item model. The current item definition at `src/main/resources/assets/arcane/items/arcane_tome.json` points to the block model, while `src/main/resources/assets/arcane/models/item/arcane_tome.json` is a flat/generated model. A GeckoLib export does not replace this item model.
- The existing `.bbmodel` is a Bedrock-format Blockbench project. Install the GeckoLib plugin, open the project, convert it to **GeckoLib Animated Model**, then check the project and bone names before editing. GeckoLib exports Bedrock-style geometry JSON; that is the expected GeckoLib runtime format, not a Bedrock add-on for users.

## First task for B1progame

Do these in order so the art can be integrated without guessing which renderer should use it.

1. **Make the held/inventory book first.** In Blockbench choose `File` -> `New` -> `Java Block/Item`. Name it `Arcane Tome Item`, use mod ID `arcane`, and set a 64x64 texture. Build a closed, readable book about 14x10x3 pixels, centered within Java's 16x16x16 item bounds. Add a visible spine, page edge, small gold corner guards, and one amethyst clasp. Use cuboids, then paint the UV texture. Set GUI, ground, first-person, third-person, and fixed display transforms in the Display tab. Save the source as `assets/blockbench/arcane_tome_item.bbmodel`; export the model to `src/main/resources/assets/arcane/models/item/arcane_tome.json` and texture to `src/main/resources/assets/arcane/textures/item/arcane_tome.png`. The item definition must then be wired to `arcane:item/arcane_tome` by the code integration.
2. **Improve the placed Tome.** In Blockbench install `GeckoLib Models & Animations` (`File` -> `Plugins` -> `Available`). Open `assets/blockbench/arcane_tome.bbmodel` and choose `File` -> `Convert Project` -> `GeckoLib Animated Model`. In project settings use mod ID `arcane`, object name `chessboard`, and a 64x64 texture. Keep the root pivot at `[8,16,8]`, X/Z within 0..16, and the closed book around Y=15..18. Preserve `root`, `cover`, and `spine_gilt`; improve the cover silhouette, page layers, fore-edge, spine, and restrained gold/amethyst details. The book's front is -Z.
3. **Export the placed Tome.** Choose `File` -> `Export` -> `Export GeckoLib Model` to replace `src/main/resources/assets/arcane/geckolib/models/block/chessboard.geo.json`; export animations to `src/main/resources/assets/arcane/geckolib/animations/block/chessboard.animation.json`; right-click the texture and choose `Save As` to `src/main/resources/assets/arcane/textures/block/chessboard.png`. Check that the animation export still contains `animation.arcane.chessboard.open` and a bone track named `cover`. Keep the editable `.bbmodel` and source texture under `assets/blockbench/`.
4. **Then make the six chess-piece sources.** Create Generic Model projects at `assets/blockbench/pieces/pawn.bbmodel`, `rook.bbmodel`, `knight.bbmodel`, `bishop.bbmodel`, `queen.bbmodel`, and `king.bbmodel`. Each piece should have a centered base pivot at Y=0, a maximum 3x3-pixel footprint on a 4x4-pixel square, and respective heights of 7, 8, 9, 10, 11, and 12 model pixels. Make a stepped pawn, battlement rook, angular horse-head knight, slit-top bishop, layered crown queen, and cross-crown king. Use a shared 32x32 pixel-art palette: warm ivory for white, deep plum for black, gold trim, and small amethyst accents. Send the source projects and front/three-quarter screenshots; Java integration is still needed before the game can use them.

The Tome is anchored to one placed block entity. Its deployed board can extend to about a 2×2-block visual footprint around that anchor. The model must not imply terrain is removed. The code will check the space before deployment. Leave the underside at model Y=0, centered on the anchor; X/Z are centered, and -Z is the front. Minecraft uses 16 model pixels per block.

## Future Tome and unfolded-board extension (not loaded by the current renderer)

`arcane_tome.bbmodel` is one model for the placed closed book, open selection book, and deployed chess scene. Keep the persistent pieces and moving parts in separate bones, with these exact names:

```text
root
book_base
book_spine
cover_left
cover_right
pages_left
pages_right
board_deck
board_frame
tiles
piece_anchor_00 ... piece_anchor_31
```

The 32 piece anchors are empty bones positioned over the starting squares; the Java renderer will place each live piece from authoritative chess state. Do not bake the starting position into the book texture. The chessboard has 64 equal squares, a one-pixel trim, oak and espresso wood, restrained gold corner details, and no painted highlights. Make the deployed squares large enough that the tallest king stays visually distinct. The 2×2-block board surface corresponds to 32×32 model pixels. The book before deployment should fit within the anchor block's 16×16 footprint.

These clips are a future animation target. Only the cover-opening clip is connected in the current Java controller. When we add the triggers, keep transitions deterministic and short; the server selects the scene state, while clients play the corresponding clip locally. No animation may change the chess rules or position.

| Clip name | Intended motion |
|---|---|
| `animation.arcane_tome.idle_closed` | Subtle, near-static closed-book settle; no constant bobbing |
| `animation.arcane_tome.open_menu` | Covers hinge open, pages fan to menu pose |
| `animation.arcane_tome.deploy_board` | Pages spread, board deck unfolds from the book, gold trim settles |
| `animation.arcane_tome.close_board` | Board folds safely back to open book |
| `animation.arcane_tome.piece_appear` | Piece anchors lift pieces into their start squares with a small stagger |
| `animation.arcane_tome.move_piece` | One piece rises, travels, and settles; code supplies source/destination |
| `animation.arcane_tome.capture_piece` | Captured piece shrinks/fades or lifts away, then moving piece settles |
| `animation.arcane_tome.castle` | King and rook move together |
| `animation.arcane_tome.victory` | Brief restrained gold/amethyst flourish; no continuous particles |

For dynamic moves, keep the geometric rest pose at its anchor. The animation/controller must allow source and target coordinates to be supplied by code; do not create one hard-coded animation per chess square. Use separate left/right side piece textures or leave material regions addressable for Java-applied side themes. Avoid transparent full-board overlays so shader packs and depth sorting remain predictable.

## Piece projects

Each piece project should have a centered underside pivot, footprint no larger than 3×3 model pixels (one chess square is 4×4 pixels), and a base at Y=0. Suggested maximum heights: pawn 7 px, rook 8 px, knight 9 px, bishop 10 px, queen 11 px, king 12 px. Build recognizable silhouettes only from stacked/rotated cuboids: battlement rook; angular horse-head knight; marked split-top bishop; layered queen crown; cross-crown king; stepped, cube-rounded pawn head. Use a shared geometry language so classic, royal, and enchanted palettes can be applied without tripling runtime geometry.

## Future exports after renderer integration

Keep the `.bbmodel` sources under `assets/blockbench/`. Also export the GeckoLib 5 runtime model, animation JSON, and PNG using the GeckoLib plugin. The target runtime paths are:

```text
src/main/resources/assets/arcane/geckolib/models/block/chessboard.geo.json

```

Use the GeckoLib 5 export format, not Bedrock entity exports or Minecraft Java Block/Item JSON. Preserve bone names, UVs, pivots, and animation names exactly. Do not add particle or sound keyframes until the Java events are wired; send those ideas as notes so they cannot silently fail in-game.

The build declares GeckoLib 5.5.7. `GameBoardBlockEntity` implements `GeoBlockEntity`; `BoardSceneRenderer` extends `GeoBlockRenderer` and submits the existing dynamic chess scene after the GeckoLib model. The opened/closed presentation state is synchronized and persisted. The initial model and animation compile as packaged resources, but runtime loading, animated-world visual review, and performance/shader checks remain pending. The separate chess-piece cuboids are still code-built and do not yet use GeckoLib bones.
